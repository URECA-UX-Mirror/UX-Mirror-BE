# 외부 사이트 시나리오 안전 검사 연동 (#68)

`uxm.scenario_safety`는 등록된 단일 사이트의 후보·클릭 직전 주소·이동 후 주소를 확인하는 독립 모듈이다. 현재 `develop`에는 #67의 시나리오 후보 추출·클릭 경로가 없으므로 자동으로 호출되지 않는다. 아래 연결과 실제 사이트 검증을 끝내기 전에는 외부 사이트 탐색이 보호된다고 가정하지 않는다.

## 설정 및 호출 계약

- 서버가 등록한 신뢰할 수 있는 사이트 설정의 실행 주소를 `base_url`로, 허용할 각 화면 URL을 `pages`에 넣어 `ScenarioSafety(base_url, tuple(pages))`를 Run마다 생성한다. 사용자가 URL 목록을 임의로 지정하지 않는다.
- 이 안전 검사는 **같은 scheme·host·port**와 등록한 화면의 경로·쿼리가 모두 일치할 때만 통과한다. 쿼리 키·값의 추가·누락·변경과 순서 변경을 허용하지 않는다. 예를 들어 `/product/list.html?cate_no=23`을 허용하려면 쿼리까지 설정에 등록해야 한다. 쿼리를 무시하기로 한 #67 초안과 다르므로 API·후보·pageKey·사전 검사·지도 생성 쪽에 같은 규칙을 반영한 뒤 통합한다.
- 시나리오 후보 추출은 `SCENARIO_LINK_SELECTOR`(`a[href]`)만 대상으로 한다. 각 링크에 대해 `candidate_rejection(current_url, candidate)`가 `None`인 경우만 후보로 제공한다. candidate는 실제 DOM의 `tag`, `href`, 보이는 `label`, `onclick`, `download`, `target`, `role`을 포함한다. 없는 HTML 속성은 `None`으로 전달한다.
- 클릭 직전에는 후보 추출 시의 값만 믿지 말고 실제 요소를 다시 찾아 위 속성을 다시 읽고 `candidate_rejection`을 재호출한다. 주소·라벨·속성이 바뀌었거나 검사가 실패하면 클릭하지 않는다.
- 이동 후에는 `arrival_rejection(page.url)`을 호출하고, 거부되면 #67의 범위 밖 이동 처리와 Event 기록을 수행한다. 이동 후 검사는 이미 전송된 요청을 취소하지 않는다.
- 기본 MORO MARKET 실행은 기존 함수와 규칙을 그대로 쓴다. 시나리오 모드에서만 이 검사를 명시적으로 적용한다.

## 한계 및 남은 통합

허용 링크의 서버 측 부작용이나 `addEventListener` 등으로 등록된 JS 동작은 주소·라벨·HTML 속성만으로 판별할 수 없다. 사전 등록 화면도 실제로 읽기 전용인지 검토하고, 위험 URL·동작은 테스트해야 한다. 리다이렉트가 다른 주소로 요청을 보내기 전에 차단해야 한다면 브라우저 네트워크 요청 제어가 별도로 필요하다.
